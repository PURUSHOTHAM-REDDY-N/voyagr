

# Voyagr - Free AI Travel Planner

Voyagr is a free AI travel planner that turns a simple prompt - like "2 days trip to London with budget $1000" - into a complete, personalized travel itinerary.

## Key Functional Features

- **Top Spots Unveiled:** Discover hidden gems and popular attractions effortlessly.
- **Tailored Itineraries:** Plan your days seamlessly with custom-tailored schedules.
- **Optimal Timing:** Learn the best time to visit your destinations for an unparalleled experience.
- **Foodie Hotspots:** Indulge in culinary delights with recommendations from local experts.
- **Prime Experiences:** Immerse yourself in unforgettable moments curated just for you.
- **Expense Tracker:** Effectively track your expenses throughout your journey and revisit them later.
- **Email Invite:** Invite friends and colleagues to your plan and collaborate together.
- **Community Plans:** Browse and get inspired by travel plans shared by other users.

## Installation

To run Voyagr locally:

1. Clone this repository and `cd` into the project directory.
2. Install the dependencies: `npm install`
3. Copy `.env.sample` to `.env` and fill in the required values (MongoDB connection string, AWS S3 credentials, Auth.js secret, etc).
4. Push the Prisma schema to your database: `npx prisma db push`
5. Start the development server: `npm run dev`
6. Open [http://localhost:3000](http://localhost:3000) to see the app in action.

### Running with Docker

1. Copy `.env.sample` to `.env` and fill in the required values, same as above. Values must be **unquoted** (`KEY=value`, not `KEY="value"`) - Docker's env-file loading doesn't strip quotes the way `dotenv` does. `DATABASE_URL` can be left as-is - Compose ignores it and points the app at the bundled MongoDB container instead (see below).
2. Build and start: `docker compose up --build`
3. Open [http://localhost:3000](http://localhost:3000).

This starts three containers: `mongo` (MongoDB, running as a single-node replica set - required by Prisma's Mongo connector), `migrate` (a one-shot job that pushes `prisma/schema.prisma` to it, then exits), and `app` (the Next.js server, which waits for `migrate` to finish). Mongo's data persists in a named Docker volume (`mongo_data`) across restarts. Ollama remains an external service reached over the network via `OLLAMA_URL`, not containerized here.

To point the containerized app at an external MongoDB (e.g. Atlas) instead of the bundled one, remove the `DATABASE_URL` override and the `mongo`/`migrate` services from `docker-compose.yml`.

## Technologies Used

- **Next.js 14:** Leveraging the latest advancements in Next.js for efficient web application development.
- **Tailwind CSS with Shadcn-UI:** Utilizing Tailwind CSS with Shadcn-UI for responsive and visually stunning user interfaces.
- **MongoDB + Prisma:** Backend data storage, accessed through Next.js Route Handlers under `app/api/**`.
- **AWS S3:** Storage for AI-generated plan cover images.
- **Local LLM via Ollama:** Itineraries are generated by a locally-hosted model (configurable via `OLLAMA_URL`/`OLLAMA_MODEL`), not a paid third-party API.
- **Auth.js (NextAuth):** Email/password authentication with JWT sessions, backed by our own Prisma `User` table.
- **Nodemailer:** For sending email invites, over plain SMTP (configurable via `SMTP_HOST`/`SMTP_USER`/etc. - works with any provider).
